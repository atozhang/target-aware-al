# Qualitative Wittig study (Fig 3E)

One active learning study on all 967 Wittig reactions (`data/Wittig/`), separate
from the 118-task benchmark. Study ID `wittig_f119_qualitative_k16_cl12`.

## Design

- **UMAP.** `umap_1` and `umap_2` embed all 967 reactions: the 119 F119
  descriptors, standardized over all rows, mapped with
  `umap.UMAP(n_components=2, n_neighbors=20, min_dist=0.18, metric="euclidean",
  random_state=42)`, with no further transformation of the coordinates.
- **Target set (63 reactions).** Ward cluster 12 of 16 (agglomerative clustering
  of the standardized F119 descriptors), restricted to the cluster's largest
  connected component on the F119 UMAP (points closer than 1.0 UMAP unit are
  linked). The cluster's three other members remain in the pool.
- **Pool (904 reactions).** All other reactions. For each seed (0, 1, 2), 25 pool
  reactions form the initial labeled set and the remaining 879 are acquisition
  candidates.
- **Acquisition.** 25 sequential acquisitions, one reaction per step, with EPIG,
  BALD and Indiv. NN (`IndvNN`). The model is a 32-member bagged XGBoost
  regressor on logit-transformed %Z, refitted after every acquisition; the
  descriptors are the F119 descriptors of the carbonyl component, ylide and cis-
  and trans-oxaphosphetanes.
- Fig 3E shows seed 1.

## Files

| File | Contents |
|---|---|
| `split_membership.csv` | One row per reaction (967, literature rows then CAS rows, as in `data/Wittig/`): `record_id`, `source`, the role in each seed (`role_seed0`–`role_seed2`: `target`, `initial` or `candidate`) and the F119 UMAP coordinates (`umap_1`, `umap_2`), the map of Fig 3C and Fig 3E. |
| `acquisitions.csv` | The 225 acquisitions (3 seeds × 3 methods × 25) in order: `study_id`, `seed`, `method`, `acquisition_rank` (1 = first), `record_id`, `source`, `acquisition_score` (value of the acquisition function for the selected reaction) and the reaction chemistry. |
| `figure_3e_reactions.csv` | The 12 reactions shown in Fig 3E: `badge`, `group` (`target`, `EPIG`, `BALD`, `IndvNN`), `seed`, `acquisition_rank`, `record_id`, `source` and the reaction chemistry. |

Reaction chemistry columns:

- `z_selectivity_percent` (the dataset value), `e_z_ratio` (E:Z) and
  `major_isomer` (`Z`, `E` or `1:1`);
- `carbonyl_smiles` and `ylide_smiles`;
- `z_alkene_smiles` and `e_alkene_smiles`, the two alkene products, named by the
  CIP descriptor of the new C=C bond;
- `product_smiles`, the major alkene (both alkenes for 1:1), and
  `reaction_smiles`, written `carbonyl.ylide>>product_smiles`;
- `product_provenance`: literature alkenes are derived from the recorded cis- and
  trans-oxaphosphetanes (the products of `rxn_smiles` in
  `data/Wittig/wittig_literature_f119.csv`) by stereospecific syn-cycloreversion;
  CAS alkenes are the product isomers recorded in the CAS reaction record;
- `ylide_provenance`: `as recorded`, or the curated ylide where the CAS record lists
  its precursor;
- `notes`: records that need a stereochemical or structural annotation.

The alkene reaction SMILES describe the reactions; descriptors and model inputs
are those of `data/Wittig/` and do not use them.

## Reproduction

```bash
python scripts/wittig_qualitative_study.py --split-only   # target, initial and candidate sets (seconds)
python scripts/wittig_qualitative_study.py                # the split and all 225 acquisitions (about 6 min, one core)
```

The script reads `data/Wittig/` and the UMAP coordinates in `split_membership.csv`,
regenerates the split and the acquisitions, and compares them with the files in
this directory (`--out DIR` also writes the regenerated tables). It requires
`xgboost` (pinned in `environment.yml`). The chemistry columns are not
regenerated by the script.

```bash
python scripts/wittig_umap_embedding.py   # regenerates umap_1 / umap_2 and compares them with split_membership.csv
```

Install the optional UMAP stack without changing the core environment:

```bash
pip install -e ".[umap]"
```

The pinned extra uses umap-learn 0.5.11, numba 0.63.1, llvmlite 0.46.0 and
pynndescent 0.5.13. With the core pins in `environment.yml` on Linux x86-64,
it reproduces the released coordinates exactly. Other versions or platforms
can give a different layout; the released coordinates are the input of the
split and of Fig 3C and Fig 3E.
